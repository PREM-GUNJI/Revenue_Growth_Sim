# ADR-016: A decision flow on the focal brand, an INR money scale, and sourced assumptions

Status: accepted (built; two performance budgets still open, see Consequences)

Context: The simulator's engine met most of the brief (deterministic, bounded by a support envelope, refusals, bands, hashes), but the app did not read as a decision tool. Pages mirrored engine internals, showed percentages with no baseline, mixed an unlabelled "$" scale in the engine with INR in the UI, and summed all three brands (Aurora, Boreal, Comet) into one "portfolio", so a competitor's profit counted as the user's. Bands in the UI were sums of per-SKU quantiles, which is not a quantile of a sum.

Decision:
- **Focal brand.** `FOCAL_BRAND = "Aurora"` in the registry module. The engine now returns `focal` (volume, revenue, net sales, gross profit) whose bands come from per-draw sums, checked against a brute-force reference in `tests/unit/test_focal_totals.py`. Competitor SKUs stay in the model for cross-price effects only. `portfolio_gp` (all brands) is still returned and still ranks on request, but the agent, the evals, the UI and the deck use the focal brand.
- **INR.** Generator prices equal the reference shelf prices A-028..A-031 for Aurora (competitors priced below it); unit costs A-013..A-015 are in INR. Elasticities are unchanged. Data and result hashes changed on purpose (engine 1.2.0, generator 1.1.0). A test pins the engine's Aurora prices to the registry's INR reference prices.
- **Sources on every assumption.** `Assumption.reference` is required for every registered assumption (enforced by `tests/unit/test_assumption_sources.py`) and shown in the assumptions drawer. References are context only: the scanner-data meta-analysis and the MSI paper on observational versus experimental elasticities explain why each elasticity carries a range; there is no public source for a manufacturer's cost structure and the references say so. Nothing is fitted.
- **Situation endpoint** (`GET /situation`): baseline P&L per pack from the engine's zero-change scenario, observed price gaps and promotion history from the synthetic history, and engine probes (a 3% price rise and a 10% promotion on each pack, and an 8% input-cost shock) compared with the baseline. Each section is labelled Observed, Modeled or Assumed.
- **Per-result explanations.** `/scenarios/evaluate` and the sweep add `assumption_ids` (decided by what the scenario changes) and `focal_bridge` (the per-SKU bridge summed for Aurora; integers, so the parts add up exactly).
- **Agent.** A `get_baseline` tool feeds a compact baseline, including the probes, to the planner; ranking and the Pareto flags use focal gross profit; `explain_scenario` and `evaluate_scenarios` return the bridge in rupees so quoted figures ground.
- **The app is organised as four steps inside a case:** Situation, Options, Compare, Recommend, with the assistant available on every step. A case is a workspace whose description is its business question (no schema change).
- **Honest benchmark.** `benchmarks/bench_engine.py` now evaluates distinct, in-support scenarios; the earlier harness repeated 13 scenarios and the engine's duplicate shortcut hid the real cost.

Consequences:
- The engine's result type gained `focal`; the API gained `assumption_ids`, `focal_bridge`, an `X-Engine-Ms` header and `/situation`. All additive.
- Result hashes, the data hash and the README worked examples differ from before; the README examples are regenerated by `scripts/generate_readme_examples.py` (restored; it had been deleted).
- **AC-016 is open at 1,000 and 10,000 scenarios**: p95 334 ms and 3,772 ms against 250 ms and 2 s. Reaching them needs lazy or columnar results, not more tuning. The thresholds were not changed.
- Still not modelled: channels, retailers, competitor reaction (A-018), promotion ROI by event, calibration to real data. The back-test's 57% band coverage (nominal 80%) is unchanged and is a self-consistency check only.
- `docs/plan/CAPSTONE_COMPLIANCE.md` expects a timed manual-spreadsheet baseline (`reports/baseline_manual.md`). It does not exist and has not been fabricated.
