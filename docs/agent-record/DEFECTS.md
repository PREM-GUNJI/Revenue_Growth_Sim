# Defect log

Every defect that review or CI caught, honestly recorded: what it was, how it was caught, and what rule/hook/test was added to prevent recurrence. A log with zero entries by submission time is not credible (`docs/plan/CAPSTONE_COMPLIANCE.md` section 6.4) — do not let this stay empty.

| # | Phase | Defect | How caught | Prevention added |
|---|---|---|---|---|
| 1 | Frontend scaffold (post-Phase 0) | The `block_destructive_bash.py` hook's `rm -rf` regex captured everything to the end of the whole command string, not just the current shell segment. `cd frontend && rm -rf dist && cat /tmp/vite-dev.log` (a safe in-repo cleanup) was blocked because the unrelated `/tmp/vite-dev.log` later in the same line was swept into the "targets" list and flagged as outside the repo. | Hit live while starting the Vite dev server for a real verification check; confirmed by re-running the five hook pipe-tests, one of which regressed | Hook now splits the command on `&&`/`\|\|`/`;`/newline before matching `rm -rf`, so later unrelated segments can't be captured. Regression case added to the hook's standard test set (see commit). Known residual limitation: it's regex-based, not a real shell parser — quoting and subshells can still fool it either way; it is a safety net, not a security boundary. |
| 2 | Phase 2 (model back-test) | The tornado sensitivity report's first reference scenario (price_index=1.0, no promo) was mathematically degenerate: `ln(1.0)=0` and `depth=0` zero out every price and promo term in the demand formula regardless of the assumption's value, so every one of the 12 assumptions showed exactly 0.0 spread. The report would have shipped looking plausible (a sorted table with real-looking labels) while being entirely uninformative. | Caught by reading the generated `reports/model_backtest.md` by eye before writing its test — the "0.0" column was an obvious tell. Not caught by any test, since no test yet asserted a non-degenerate spread. | Switched to a stress reference scenario (+8% price, 15%-depth promo, mechanics cycled across SKUs) that actually exercises every drawable parameter. Added `test_tornado_top_assumption_has_nonzero_spread` so a future regression to a degenerate metric fails a test, not just a visual check. |
| 3 | Phase 2 (model back-test) | `Path.write_text()` without an explicit `encoding="utf-8"` mangled the report's em-dash characters into `�` on this Windows machine (default locale encoding, not UTF-8). | Visual inspection of the generated `reports/model_backtest.md`. | Added `encoding="utf-8"` to every `write_text()` call that writes non-ASCII content (`generator.py`'s manifest, `backtest.py`'s manifest and report). No automated test added — this is a one-line convention now applied at every call site; worth a lint rule if more such calls accumulate later. |
