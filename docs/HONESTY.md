# HONESTY.md: what's real, what's scaffolded, what's still open

This is the honest engineering record CAPSTONE_COMPLIANCE.md requires: a
plain account of what actually runs today, what is still a stub, where
numbers came close to a stated budget, and every deliberate deviation from
the original plan. It is built from `docs/agent-record/REVIEW_LOG.md` and
`docs/agent-record/DEFECTS.md` (the primary sources of truth) rather than
asserting anything new.

## What is real

- **Engine** (`backend/engine/`, `backend/model/`, `backend/assumptions/`):
  fully vectorised, deterministic, every number traced through
  `registry.get("A-xxx")`. No fitting, no ML, per CLAUDE.md. Property-based
  tests (Hypothesis) back the zero-change-is-baseline, monotone-price-volume,
  bridge-sums-exact and batch-equals-single invariants (AC-006..009).
- **Support envelope / refusal** (`backend/engine/support.py`): a scenario is
  REFUSED whole, never clamped, with a labelled 500-point recall/precision
  check (AC-010/011/012).
- **Assumptions registry** (`backend/assumptions/registry.py`): read-tracked,
  100% coverage enforced by `tests/unit/test_registry_coverage.py` (AC-005).
- **Agent core** (`backend/agent/`): Planner/Executor/Auditor loop, typed
  tools with no filesystem/network/engine-internals access, numeric
  grounding, Observed/Modeled/Assumed/Recommended claim labelling, JSONL
  trace + deterministic replay. All offline-testable via `ScriptedLLM`
  (Phase 10-13 rule), verified real by `tests/agent/*` and the Phase 14
  43-task eval suite (`agent_evals/`), currently green on every budget (see
  below).
- **Live LLM provider** (`backend/agent/openai_llm.py`): real OpenAI
  `responses.parse` structured-output integration, but it is never on the
  path of any test or CI job — `tests/agent/test_openai_llm.py` exercises it
  against a fake client only (ADR-012).
- **Optional Postgres persistence** (`backend/db.py`, `POST /scenario-runs`,
  `GET /scenario-runs`): real SQLAlchemy/psycopg code, gated entirely behind
  `DATABASE_URL`; absent it, the endpoint returns 503 and nothing else in the
  engine or agent touches a database (ADR-012).
- **Frontend** (`frontend/`): builds and runs against the live API
  (comparison board, tray, refusal cards, assumptions drawer, trade-off
  plane, bridge waterfall, agent panel). Production build (`npm run build`)
  passes; this is now exercised headlessly in CI by
  `.github/workflows/clean_clone.yml` / `uv run python -m tasks demo-check`.
- **README worked examples**: generated by `scripts/generate_readme_examples.py`,
  which runs the real engine (`evaluate_batch`) and the real scripted agent
  loop (`AgentOrchestrator` + `ScriptedLLM`) and embeds the actual output
  between `<!-- BEGIN/END GENERATED WORKED EXAMPLES -->` markers in
  `README.md`. Nothing in that section is hand-typed; re-run the script to
  regenerate it after an engine/agent change.
- **AC traceability** (`tests/test_ac_traceability.py`, new this phase):
  scans `tests/`, `agent_evals/`, `benchmarks/` and `.github/workflows/` for
  every AC-xxx id defined in `docs/spec/BRD.md` and fails the build unless
  each one is named by a test/workflow or is an explicit, defect-logged gap.

## What is scaffolded / stubbed

- **Deployment** (Phase 19): `tasks.py`'s `smoke` and `rollback` targets are
  still `"not yet"` stubs. No Dockerfile/compose rollout has been exercised
  end to end yet, and `docs/ops/ROLLBACK_EVIDENCE.md` does not exist (logged
  as AC-027 in `KNOWN_GAPS`, expected — Phase 19 has not started).
- **Browser-level e2e** (AC-024): `tests/e2e/` only has `__init__.py`. No
  Playwright test exists yet that actually renders a board with a losing and
  a refused scenario and asserts the red tag / greyed refusal card / "use
  nearest supported" action. REVIEW_LOG's Phase 8-9 entry already flagged
  "no Playwright run"; this was never closed in Phase 15 and is logged again
  here as DEFECTS.md #13.
- **`eval_thresholds.yaml`** (new this phase): the five Phase 14 budgets were
  previously a dict literal inside `agent_evals/run_evals.py`; they are now
  a standalone YAML file so a regression is a visible one-line diff, per
  AC-026. The `eval-gate` CI job (`.github/workflows/eval-gate.yml`) re-runs
  the scripted evals against this file on every push/PR. What is *not* done:
  an actual `demo/regression` branch demonstrating a blocked PR was not
  pushed in this session (see "What was deliberately not done" below).
- **Security** (Phase 18): bandit/pip-audit/gitleaks already run in CI
  (`security` job) per the Phase 18 REVIEW_LOG entry, but that phase's own
  acceptance items (TRIAGE triage completeness, AGENT_BOUNDARY runbooks for
  every surface) are tracked separately and are outside Phase 16-17's scope.

## ADR-012: the OpenAI + Postgres deviation

CLAUDE.md names "LLM: Anthropic Claude via tool use" and no database; the
user chose, mid-project, to use OpenAI's structured-output API as the live
agent provider and to add optional PostgreSQL persistence for scenario run
history. `docs/spec/adr/ADR-012-openai-live-provider-and-postgres-persistence.md`
records this as a deliberate, scoped deviation:

- The **deterministic test path never changes**: `ScriptedLLM` remains the
  only provider used by the Planner/Executor/Auditor tests, the grounding
  tests, the replay tests, and the Phase 14 CI eval gate. No test imports or
  calls `OpenAILLM` against a live network.
- The **live path is additive**: `OpenAILLM` and `backend/db.py` are only
  reachable through `POST /agent/run` and `POST/GET /scenario-runs`, both of
  which degrade explicitly (503, or a clearly documented "later phase" note)
  when `OPENAI_API_KEY` / `DATABASE_URL` are absent.
- This is a real stack deviation, not a hidden one: it is called out in
  `CLAUDE.md`'s own "Stack" section header ("deviates from `docs/plan/PLAN.md`
  by agreement — see ADR-009, ADR-010") pattern, extended by ADR-012, and is
  repeated here per this document's purpose.

## Where a metric or test was close to its budget

- **Phase 7 engine latency** (AC-016): the REVIEW_LOG Phase 7 entry recorded
  a real miss on this host — p95 51.33 ms / 455.33 ms / 4,492.36 ms at
  100/1,000/10,000 scenarios against budgets of <50 ms / <250 ms / <2,000 ms
  — before the vectorisation/bulk-quantile fixes landed. `benchmarks/bench_engine.py`
  is the permanent gate; re-run it on the target host before trusting the
  budget is met there, since these numbers are host-dependent (the REVIEW_LOG
  entry is explicit about "this Windows host").
- **Phase 14 agent evals**: all five budgets (grounding 100%, refusal
  integrity 100%, injection resistance 100%, label correctness 100% against
  a >=95% budget, optimality gap median 0.0% against a <=2% budget) are
  currently met with real margin on the scripted-LLM suite (43/43 tasks,
  `reports/agent_evals.json`) — not "close," but it is worth noting this is
  the *scripted* LLM; a live OpenAI run (`--live`) has not been evaluated
  against the same budgets in CI (deliberately, per the Phase 10-13
  determinism rule) and could plausibly fall below the grounding/label
  budgets a less constrained free-text model might produce.
- **Phase 4 retailer-risk flag**: DEFECTS.md #5 recorded a genuine near-miss
  — the first formula's float rounding put the baseline case a hair below
  the hurdle rate, firing a false positive at `price_index=1.0`. Fixed
  algebraically so the baseline case is exact in float, not just close.

## What was deliberately not done in this phase (16-17)

- A `demo/regression` branch that deliberately lowers `eval_thresholds.yaml`
  and shows `eval-gate.yml` blocking the PR was **not pushed**, per this
  session's explicit instruction to leave all changes uncommitted for
  review. `.github/workflows/eval-gate.yml`'s header comment documents the
  exact two-step reproduction (lower a threshold, open a PR) so it can be
  demonstrated once changes are committed.
- `uv run python -m tasks demo-check` was verified locally: the API half
  (start uvicorn, poll `/healthz`, call `/assumptions`) passes cleanly. The
  frontend `npm ci` half hit a Windows-only file lock
  (`EPERM: operation not permitted, unlink ... rolldown-binding...node`) on
  this dev machine's existing `node_modules`, almost certainly an antivirus
  or stale-handle issue specific to this host, not a bug in the check
  itself — `.github/workflows/clean_clone.yml` runs the same command on a
  fresh ubuntu-latest runner with no pre-existing `node_modules`, where this
  class of lock cannot occur. Flagged here rather than silently assumed to
  work everywhere.

## Synthetic consumer evidence layer (Phase 21)

Real: deterministic synthetic respondents and comments, WTP / Gabor-Granger / Van Westendorp rules, a multinomial-logit conjoint *simulation*, the candidate-to-engine bridge with provenance, refusal of unsupported candidates, agent evidence tools and the research-aware claim rules. All covered by AC-028..AC-033.

Not real, by design: the respondents, comments and part-worths are synthetic and illustrative; no utility estimation or fitting exists; no real consumer research is claimed; no causal claim is made. Van Westendorp is computed from synthetic four-question answers derived from each respondent WTP, so its price points describe the generator more than any market. The "larger pack" joint presets express pack steering as relative price/promotion positioning because the engine has no pack-swap lever (ADR-013).

Open: BPTO and Price Ladder (optional in the request) are not implemented; the live OpenAI planner has the research field in its schema but its method choice is covered by prompt guidance, not by an offline eval.
